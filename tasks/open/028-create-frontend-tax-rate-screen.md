# 028 フロントエンドの税率マスタ画面を作成する

## 目的

税率マスタをブラウザから確認・登録できるようにし、売上日に応じて適用税率を選ぶ業務ルールを画面から学習できるようにする。

## 前提タスク

- `024-redesign-api-contracts-around-aggregates.md`
- `025-refactor-master-apis-around-aggregates.md`
- `026-refactor-sales-api-contracts.md`
- `027-update-existing-master-frontends-for-new-apis.md`

## 対象範囲

- Next.js フロントエンドに税率マスタ画面を追加する。
- 税率一覧を表示する。
- 税率の新規登録フォームを作成する。
- 指定日時点で適用される税率を確認できるようにする。
- 税率 API 呼び出し処理と TypeScript 型を整理する。
- ローディング、入力エラー、API エラーを画面上で確認できるようにする。

## 前提仕様

- 税率は商品マスタとは別に管理する。
- 商品履歴の税区分と売上日から、適用する税率を決定する。
- 適用する税率は、売上日以前で一番新しい税率とする。
- 得意先別商品単価は単価決定に使い、税率決定には使わない。
- 同じ税率値でも、税区分が異なる場合は別の適用情報として扱う。
- 税率履歴行 ID は通常画面へ表示しない。
- バックエンド API はダミー認証を使うため、フロントエンドから必要なヘッダーを付与する。

## 実装方針

- 商品マスタ画面または得意先マスタ画面で作成した API クライアントや UI パターンがあれば、それに合わせる。
- 一覧、登録フォーム、指定日時点の確認を同じ画面内で扱える構成にする。
- 一覧では税区分コード、税区分名、会計分類、税率、適用開始日を確認できるようにする。
- 画面と API クライアントはタスク 024、025 で確定・実装した契約を使用する。
- API のレスポンス型は TypeScript で定義し、画面側に ad hoc な `any` を広げない。

## 確認項目

- `bun lint` またはプロジェクトで定義されているフロントエンド検証コマンドが成功すること。
- 税率を新規登録できること。
- 税率一覧が登録後の内容を反映すること。
- 指定日時点の確認で、対象日以前で一番新しい税率を確認できること。
- 同じ税率値でも税区分名と会計分類を区別して表示できること。
- API エラー時に画面がクラッシュせず、ユーザーに原因が分かる表示になること。
