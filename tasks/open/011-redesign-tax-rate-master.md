# 011 税率マスタを再設計する

## 目的

売上明細で適用する税率を、税率値だけでなく会計集計上の税区分として扱えるように、税率マスタの仕様とバックエンド実装を見直す。

軽減税率 8% と旧標準税率 8% は税額が同じでも会計資料では別集計が必要なため、税率値だけで同一視しない。

## 背景

現在の `TaxRates` は `TaxCategory`, `Rate`, `ValidFrom` のみを持つ。

この構造では、標準税率、軽減税率、非課税、免税、旧標準税率を業務上の区分として明確に扱いづらい。また、売上明細に税率値だけを保存すると、同率の税区分を後から区別できない。

## 対象仕様

- `specs/tax-rates.md`
- `specs/sales-entry.md`

## 実装内容

- `specs/tax-rates.md` を更新し、税率マスタの再設計方針を明記する。
- 税率マスタで扱う税区分を定義する。
  - 標準税率
  - 軽減税率
  - 非課税
  - 免税
  - 旧標準税率
- 税率値が同じでも税区分コードが異なれば別レコードとして扱う。
- 今後の税率変更に備え、税区分ごとに履歴レコードを追加する方針を維持する。
- `TaxRate` エンティティと EF Core 設定を見直す。
- 必要なマイグレーションを追加する。
- 税率マスタ API の DTO、バリデーション、レスポンスを見直す。
- 既存テストを新しい税率マスタ仕様に合わせて更新する。

## 検討項目

- 税区分コード、表示名、会計集計用分類をどのカラムで持つか。
- 非課税と免税の税率値を `0.0000` として扱うか。
- 旧標準税率を通常の税率履歴として扱うか、税区分として明示的に分けるか。

## テスト観点

- 標準税率、軽減税率、非課税、免税、旧標準税率を登録できる。
- 同じ税率値でも異なる税区分として登録できる。
- 税区分ごとに売上日以前で一番新しい税率を取得できる。
- 初回 `ValidFrom` より前の日付では税率が取得できない。
- 既存売上明細の保存値が、税率マスタ変更後も変わらない。
