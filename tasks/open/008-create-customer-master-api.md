# 008 得意先マスタ API を作成する

## 目的

得意先マスタの一覧取得、新規登録、履歴追加、履歴参照、指定日プレビューを行う Web API を作成する。

得意先マスタは売上登録時に採用する得意先履歴の元になるため、商品マスタと同じ履歴管理ルールで扱えるようにする。

## 背景

`004-create-backend-tables.md` で `Customers` と `CustomerVersions` のテーブル定義、制約、マイグレーションは作成済みである。

売上登録 API では売上日以前で有効な得意先履歴を採用して `CustomerVersionId` を保存するため、先に得意先マスタ API を作成する。

## 対象仕様

- `specs/customer-master.md`
- `specs/sales-entry.md`
- `specs/overview.md`

## 実装内容

- `Features/Customers` 配下に得意先マスタ API の実装を追加する。
- `Program.cs` から得意先マスタ API のエンドポイントを登録する。
- 得意先マスタ API に認可要件を設定する。
  - 参照系 API は `AuthenticatedUser` を要求する。
  - 登録・履歴追加 API は `MasterMaintainer` ロールを要求する。
- 得意先一覧 API を作成する。
  - 得意先コード、得意先名で絞り込めること。
  - 現在日付時点で有効な得意先履歴を一覧に表示すること。
- 得意先新規登録 API を作成する。
  - `Customers` を追加すること。
  - 初回の `CustomerVersions` を同時に追加すること。
  - `CreatedAt` はアプリケーション側で UTC 現在日時を設定すること。
- 得意先履歴追加 API を作成する。
  - 既存の `CustomerVersions` は更新せず、新しい履歴を追加すること。
  - 同じ `CustomerId` と `ValidFrom` の履歴を重複登録できないこと。
- 得意先履歴一覧 API を作成する。
  - 指定した得意先の履歴を `ValidFrom` 降順で取得できること。
- 指定日プレビュー API を作成する。
  - 指定日以前で一番新しい得意先履歴を返すこと。
  - 初回 `ValidFrom` より前の日付では、適用できる履歴がないことを表現すること。
- 入力 DTO とレスポンス DTO を定義する。
- 入力バリデーションを実装する。
  - 得意先コードは必須、最大 30 文字。
  - 得意先名は必須、最大 100 文字。
  - 住所は必須、最大 300 文字。
  - 電話番号は必須、最大 30 文字。
  - `ValidFrom` は必須。
- API の正常系、異常系テストを追加する。
- 認証ヘッダーなし、ロール不足、必要ロールありの認可テストを追加する。
- 必要に応じて `.http` ファイルに手動確認用リクエストを追加する。

## 想定エンドポイント

- `GET /api/customers`
  - 得意先一覧を取得する。
  - クエリ例: `customerCode`, `name`
- `POST /api/customers`
  - 得意先を新規登録する。
- `GET /api/customers/{customerId}/versions`
  - 得意先履歴一覧を取得する。
- `POST /api/customers/{customerId}/versions`
  - 得意先履歴を追加する。
- `GET /api/customers/{customerId}/preview?targetDate=yyyy-MM-dd`
  - 指定日時点で有効な得意先履歴を取得する。

## 注意点

- マスタ変更は既存行の更新ではなく、履歴レコードの追加で表現する。
- `CustomerVersions` に `ValidTo` は追加しない。
- 指定日適用履歴は `ValidFrom <= targetDate` の中で `ValidFrom` が最大の履歴とする。
- 一覧取得でも、画面表示用の現在履歴を同じ考え方で取得する。
- SQLite では `LIMIT 1` で表現できるが、実装では Oracle 対応を見据えて EF Core の LINQ で履歴取得を表現する。
- 日付比較は業務上日付部分のみを有効とするため、時刻混入時の扱いを実装またはテストで明確にする。
- DB の一意制約違反に依存しすぎず、API として分かりやすいエラーを返す。
- ただし競合登録に備えて DB 制約違反も適切にエラー化する。

## 確認内容

- `dotnet test backend/SalesSystem.slnx` が成功する。
- 得意先を新規登録できる。
- 得意先コード重複時にエラーになる。
- 得意先履歴を追加できる。
- 同じ `CustomerId` と `ValidFrom` の得意先履歴を重複登録できない。
- 得意先一覧で現在有効な履歴の内容が取得できる。
- 得意先一覧で得意先コード、得意先名の絞り込みができる。
- 指定日プレビューで、指定日以前の最新履歴が取得できる。
- 初回 `ValidFrom` より前の指定日では、適用履歴なしとして扱われる。
- 認証なしでは得意先マスタ API にアクセスできない。
- `MasterMaintainer` ロールなしでは登録・履歴追加 API にアクセスできない。
- 履歴取得クエリが Oracle でも成立する LINQ になっていることをコードレビューで確認する。
