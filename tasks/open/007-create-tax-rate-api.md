# 007 税率マスタ API を作成する

## 目的

税区分と適用開始日ごとの税率を管理し、売上日以前で有効な税率を取得できる Web API を作成する。

税率は売上明細の税率、税額、合計金額の計算に使うため、売上登録 API より先に実装する。

## 背景

`004-create-backend-tables.md` で `TaxRates` のテーブル定義、制約、マイグレーションは作成済みである。

税率変更は既存レコードの更新ではなく新しい `TaxRates` の追加で表現するため、商品マスタや得意先マスタと同じく履歴型の取得ルールを API で扱う。

## 対象仕様

- `specs/tax-rates.md`
- `specs/sales-entry.md`
- `specs/overview.md`

## 実装内容

- `Features/Taxes` 配下に税率 API の実装を追加する。
- `Program.cs` から税率 API のエンドポイントを登録する。
- 税率一覧 API を作成する。
  - 税区分で絞り込めること。
  - `ValidFrom` 降順で取得できること。
- 税率登録 API を作成する。
  - 既存の `TaxRates` は更新せず、新しい税率レコードを追加すること。
  - 同じ `TaxCategory` と `ValidFrom` の税率を重複登録できないこと。
- 指定日プレビュー API を作成する。
  - 指定した税区分について、指定日以前で一番新しい税率を返すこと。
  - 初回 `ValidFrom` より前の日付では、適用できる税率がないことを表現すること。
- 入力 DTO とレスポンス DTO を定義する。
- 入力バリデーションを実装する。
  - 税区分は必須、最大 30 文字。
  - 税率は 0 以上、小数 4 桁まで。
  - `ValidFrom` は必須。
- 認可要件を設定する。
  - 参照系 API は `AuthenticatedUser` を要求する。
  - 登録 API は `MasterMaintainer` を要求する。
- API の正常系、異常系テストを追加する。
- 認証ヘッダーなし、ロール不足、必要ロールありの認可テストを追加する。
- 必要に応じて `.http` ファイルに手動確認用リクエストを追加する。

## 想定エンドポイント

- `GET /api/tax-rates`
  - 税率一覧を取得する。
  - クエリ例: `taxCategory`
- `POST /api/tax-rates`
  - 税率を登録する。
- `GET /api/tax-rates/preview?taxCategory=standard&targetDate=yyyy-MM-dd`
  - 指定日時点で有効な税率を取得する。

## 注意点

- 税率変更は既存レコードの更新ではなく、税率レコードの追加で表現する。
- 指定日適用税率は `ValidFrom <= targetDate` の中で `ValidFrom` が最大の税率とする。
- SQLite では `LIMIT 1` で表現できるが、実装では Oracle 対応を見据えて EF Core の LINQ で履歴取得を表現する。
- 売上登録済みの明細に保存された税率と税額は、税率マスタ変更後も変えない。
- 日付比較は業務上日付部分のみを有効とするため、時刻混入時の扱いを実装またはテストで明確にする。
- DB の一意制約違反に依存しすぎず、API として分かりやすいエラーを返す。
- ただし競合登録に備えて DB 制約違反も適切にエラー化する。

## 確認内容

- `dotnet test backend/SalesSystem.slnx` が成功する。
- 税率を登録できる。
- 同じ `TaxCategory` と `ValidFrom` の税率を重複登録できない。
- 税区分ごとに税率一覧を取得できる。
- 指定日プレビューで、指定日以前の最新税率が取得できる。
- 初回 `ValidFrom` より前の指定日では、適用税率なしとして扱われる。
- 認証なしでは税率 API にアクセスできない。
- `MasterMaintainer` ロールなしでは登録 API にアクセスできない。
- 履歴取得クエリが Oracle でも成立する LINQ になっていることをコードレビューで確認する。
