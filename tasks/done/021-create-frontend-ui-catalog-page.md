# 021 フロントエンド UI カタログページを作成する

## 目的

トップページとは別に、販売管理システムの共通 UI 部品、表示密度、状態表示、フォーム、テーブルのデザイン基準を確認できる `/ui-catalog` ページを作成する。

## 背景

トップページをデザインサンプルにすると、業務画面への入口としての役割と UI 部品確認の役割が混ざる。
トップページは業務画面への導線と接続状態の確認に絞り、UI カタログは別ページとして用意する。

## 対象範囲

- `frontend/src/app/ui-catalog/page.tsx` を追加する。
- `frontend/src/components/ui/` に、画面タスクで使う最小限の共通 UI 部品を追加または整理する。
- ボタン、入力、フォームエラー、通知、テーブル、ステータス、ダミー認証 UI の表示例を `/ui-catalog` に並べる。
- トップページ `/` から `/ui-catalog` への導線を追加する。
- UI カタログの表示確認用 Vitest または Playwright テストを追加する。
- Product Design プラグインを使い、実装前に UI カタログのブリーフを確認する。

## 前提仕様

- `specs/frontend-architecture.md` の構成方針とデザイン方針に従う。
- 業務画面は静かで情報を探しやすい UI を優先する。
- UI カタログはデモ用の派手なランディングページではなく、実際の業務画面で使う部品の基準面とする。
- `shadcn/ui` はこのタスクでは導入しない。

## 実装方針

- `/ui-catalog` は App Router の通常ページとして作る。
- 画面上のサンプルデータは、商品、得意先、税率、売上を想起できる学習用の固定データにする。
- 共通 UI 部品は、今後の `017` 以降の画面でそのまま使える粒度に留める。
- UI カタログ固有の見た目だけに依存するコンポーネントを増やしすぎない。
- テーブル、フォーム、エラー、空状態、ローディング、権限不足など、業務画面で頻出する状態を確認できるようにする。

## 確認項目

- `bun lint` が成功すること。
- `bun run test` が成功すること。
- `bun run test:e2e` または UI カタログ対象の Playwright テストが成功すること。
- `bun run build` が成功すること。
- `/` と `/ui-catalog` の役割が分かれていること。
- `/ui-catalog` で共通 UI 部品の基本状態を確認できること。

### 追加・変更した UI 部品

- `frontend/src/components/ui/input.tsx`: 通常入力、エラー状態、disabled 状態を表現できる `Input` を追加した。
- `frontend/src/components/ui/badge.tsx`: `neutral`, `success`, `warning`, `danger`, `info` の状態表示用 `Badge` を追加した。
- `frontend/src/components/ui/alert.tsx`: 成功、情報、エラー通知を表示する `Alert` を追加した。

### UI カタログに載せた表示パターン

- ボタン: primary、secondary、ghost、disabled、アイコン付き操作。
- 入力: 通常、日付、disabled、フィールド直下の日本語エラー。
- テーブル: 商品一覧、金額、税区分、状態バッジ、選択中相当の行。
- 通知: 登録成功、入力エラー、通信エラー。
- 状態: 有効、確認中、権限不足、未選択。
- 空状態、読み込み中、ダミー認証状態: 管理者、一般ユーザー、ログアウト。

### Product Design ブリーフで決めたこと

- トップページとは別に `/ui-catalog` を作る。
- UI カタログは表示確認中心の静的カタログにする。
- 見た目は販売管理システム向けの静かで密度高めの業務 UI とし、派手なデモページにはしない。
- 外部のデザイン参照は使わず、`specs/frontend-architecture.md` のデザイン方針を基準にした。

- ダミー認証 UI は静的表示に留めた。実際の切り替え、`localStorage` 保存、API ヘッダー付与は別タスクで扱う。

## デザイン修正記録

修正日: 2026-06-05

スクリーンショット確認後、UI カタログが左端に寄りすぎ、見出しやカードの階層が弱く、フォームと通知が混在して見える問題を修正した。

### 修正内容

- ページ全体に安定した横幅と左右余白を持つ `.app-shell` を追加した。
- カード、セクション見出し、テーブルセル、共通 UI 部品に専用クラスを追加し、Tailwind の spacing utility が欠落しても余白が崩れないようにした。
- UI カタログを `Tables`, `Actions`, `Status`, `Forms`, `Feedback`, `Async / Empty`, `Auth States` に分類し直した。
- フォームは 2 カラム寄りのコンパクトな配置にし、縦に長くなりすぎないようにした。
- 通知、非同期状態、空状態を別セクションに分け、表示目的が混ざらないようにした。
- バッジは丸みと色面を抑え、業務システム向けの控えめな状態表示に変更した。
- Alert は色面を弱め、左罫線とアイコンで状態を伝える見た目に変更した。
- テーブルは列幅、セル余白、選択中行の左罫線を調整し、一覧画面の基準として見やすくした。

- `bun run build`: 成功。
- in-app Browser で `http://localhost:3000/ui-catalog` を開き、左余白、カード余白、ボタン余白、テーブルセル余白が反映されていることを確認した。
