# 003: ローカル開発手順を整理する

## 目的

バックエンドとフロントエンドの開発環境を、後から迷わず再現できるように README に整理する。

## 対象範囲

- 必要なツールとバージョンの目安を README に記載する。
- 初回セットアップ手順を README に記載する。
- バックエンドの起動、テスト、DB 初期化手順を README に記載する。
- フロントエンドの起動手順を README に記載する。
- `.env.example` など、共有してよい設定例が必要であれば追加する。
- SQLite ローカル開発と Oracle 本番想定の違いを明記する。

## 技術方針

- README は学習用リポジトリとして、短くても再現性のある手順を優先する。
- 秘密情報や個人環境に依存する値は Git 管理しない。
- Oracle 互換の確認が必要な項目は、SQLite で確認済みの項目と混同しないように書き分ける。

## 完了条件

- 新しい開発者が README の手順だけでバックエンドとフロントエンドを起動できる。
- テスト実行手順が README に記載されている。
- ローカル DB と本番想定 DB の扱いが README に記載されている。

## 実装内容

- README にローカル開発で必要なツールとバージョン確認コマンドを追加した。
- README に初回セットアップ手順として `dotnet restore`、`bun install`、`.env.local` 作成を追加した。
- README にバックエンドの SQLite ファイル DB の場所、接続文字列、DB 作り直し手順を追加した。
- README に現在の DB 初期化が `GET /health` 実行時の `EnsureCreatedAsync` による最小構成であることを明記した。
- README に SQLite ローカル開発と Oracle 本番想定の違い、Oracle 上でも確認すべき項目を追記した。
- README に既存のバックエンド起動、テスト、フロントエンド起動、lint/build 手順とつながる形でローカル開発手順を整理した。

## 設計メモ

- このタスクではコード変更を行わず、後から環境を再現するための README 整備に限定した。
- SQLite の DB 初期化は現在の実装に合わせて `EnsureCreatedAsync` と記載した。正式なスキーマ変更手順は migrations 導入後に更新する。
- Oracle 互換の確認が必要な項目は、SQLite で確認できる通常のローカル起動・テストと混同しないように分けて記載した。

## 確認結果

- `dotnet test`: 成功、2 tests passed
- `bun run lint`: 成功
