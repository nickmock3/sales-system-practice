# 030 フロントエンドの売上入力画面を作成する

## 目的

売上日、得意先、商品明細をブラウザから入力し、売上登録できるようにする。

登録時点で採用される得意先情報、商品情報、税率、単価根拠、金額計算を画面上で確認できる状態にし、売上を過去の取引記録として保存する業務ルールを学習できるようにする。

## 対象範囲

- Next.js フロントエンドに売上入力画面を追加する。
- 売上日と得意先を入力・選択できるようにする。
- 商品明細行を追加、編集、削除できるようにする。
- 明細の商品選択時に売上入力補助 API から売上日時点の商品情報、税率、自動取得単価を取得する。
- 得意先別商品単価と商品標準単価へのフォールバックを区別して表示する。
- 単価の手入力変更と、任意の変更理由入力を扱えるようにする。
- 数量、単価、税率から明細金額、税額、税込金額、伝票合計を画面上で計算する。
- 売上登録 API を呼び出し、登録結果を画面で確認できるようにする。
- 登録済み売上一覧を表示し、売上日範囲と得意先で絞り込みできるようにする。
- 売上詳細を表示し、登録時点で保存された得意先名、商品名、単価、税率、税区分、金額を確認できるようにする。
- 売上 API 呼び出し処理と TypeScript 型を整理する。
- ローディング、入力エラー、API エラーを画面上で確認できるようにする。

## 前提仕様

- 売上は過去の取引記録として扱い、登録後にマスタ履歴や税率が変わっても保存済みの売上情報は変更しない。
- 売上登録時には、売上日時点で有効な得意先履歴、商品履歴、税率を採用する。
- 適用する履歴は、対象日以前で一番新しい履歴とする。
- 商品明細の自動取得単価は、売上日、得意先、商品をもとに決定する。
- 得意先別商品単価が存在する場合は、その単価を採用する。
- 得意先別商品単価が存在しない場合は、商品標準単価へフォールバックする。
- 単価を手入力で変更した場合も、登録時点の自動取得単価と単価根拠を保存する。
- 税額は明細ごとに計算し、伝票合計に対してまとめて税額計算しない。
- 登録済み売上に入力間違いがあった場合、売上ヘッダーや明細を直接更新せず、取消と再登録で訂正する。
- バックエンド API はダミー認証を使うため、フロントエンドから必要なヘッダーを付与する。

## 利用 API

- タスク 024、025、026 で確定・実装した売上 API、売上入力補助 API、得意先 API、商品 API を使用する。
- 売上入力補助 API は、売上日、得意先 ID、商品 ID から表示に必要な商品情報、税率、自動取得単価、単価根拠を返す。
- フロントエンドはマスタ履歴行 ID や得意先別商品単価履歴行 ID を扱わない。

## 実装方針

- 商品マスタ画面、得意先マスタ画面、税率マスタ画面、得意先別商品単価画面で作成した API クライアントや UI パターンがあれば、それに合わせる。
- 入力、一覧、詳細を同じ売上画面内で扱える構成にする。
- 得意先と商品は ID 入力だけに依存せず、既存の得意先一覧・商品一覧 API を使った選択補助を検討する。
- 明細行ごとにプレビュー結果を保持し、自動取得単価、手入力単価、税率、税額、金額の関係が分かる表示にする。
- 単価根拠は `CustomerProductPrice` と `ProductStandard` を画面上で区別して表示する。
- 商品標準単価へフォールバックした場合は、単価根拠の表示で確認できるようにする。
- 売上日または得意先を変更した場合、選択済み明細のプレビュー再取得が必要であることを画面状態で扱う。
- 登録時にバックエンドで再計算される値と画面表示値がずれる可能性を考慮し、登録後は売上詳細 API の結果を表示する。
- 金額計算は `specs/sales-entry.md` の丸めルールに合わせ、画面側の計算ロジックをテストできる形に分離する。
- API のレスポンス型は TypeScript で定義し、画面側に ad hoc な `any` を広げない。

## 実装結果

### 実装した画面・コンポーネント

- `frontend/src/app/sales/page.tsx` に、売上入力、売上一覧、売上詳細を同一画面で扱う売上画面を追加した。
- 売上入力は売上日、対象日時点の得意先、複数明細、伝票合計を表示し、明細の追加・削除に対応した。
- 売上一覧は売上日範囲、得意先、得意先コード、取消済・訂正売上の包含条件で絞り込めるようにした。
- 売上詳細は登録時点の得意先・商品・単価・税区分・税率・金額、状態履歴、訂正関連情報を表示する。
- 入力、明細行、一覧、詳細、登録結果を責務別コンポーネントへ分割した。

### API クライアントと型

- `frontend/src/app/sales/_api.ts` に売上一覧、売上詳細、明細入力補助、売上登録の API 呼び出しを追加した。
- `frontend/src/app/sales/_types.ts` と `_schemas.ts` に API 契約に対応する TypeScript 型と Zod スキーマを追加した。
- API レスポンスは Zod で検証し、通常画面では内部のマスタ履歴行 ID を扱わない構成にした。
- ダミー認証は既存の `apiFetch` を利用し、管理者だけが売上登録できることを画面状態に反映した。

### 売上入力補助と単価

- 商品選択時に `GET /api/sales/line-preview` を呼び、売上日・得意先・商品に対応する商品情報、税率、自動取得単価、単価根拠を明細ごとに保持する。
- `CUSTOMER_PRODUCT_PRICE` は得意先別商品単価、`PRODUCT_STANDARD` は商品標準単価へのフォールバックとして区別表示する。
- 入力単価と自動取得単価が異なる場合を手入力変更として扱い、変更理由は手入力変更時だけ登録リクエストへ含める。
- 売上日、得意先、商品変更後は明細を再取得待ちにし、変更前コンテキストの非同期応答を request ID とコンテキスト照合で破棄する。
- 販売停止、プレビューエラー、再取得待ち、対象日時点の得意先未確認がある場合は登録できないようにした。

### 金額計算と丸め

- `frontend/src/app/sales/_amounts.ts` に UI 非依存の金額計算を分離した。
- 明細金額は数量と単価の積を小数第2位へ midpoint away from zero で丸める。
- 税額は丸め後の明細金額と税率の積を明細ごとに1円未満切り捨てとする。
- 伝票合計は明細ごとの明細金額、税額、税込金額を合算する。
- 登録後は売上詳細 API の保存結果を表示し、バックエンドの計算結果を正とする。

### 残した制約・次タスク候補

- 売上取消と再登録操作は対象外とし、詳細では状態履歴と訂正関連情報の参照だけを提供する。
- JavaScript の数値計算はバックエンドの decimal と実装方式が異なるため、境界値を単体テストで固定し、登録後は API 保存結果を正とする。
- 既存 E2E の曖昧な locator は、得意先別商品単価画面の保守タスクで一覧領域へスコープする修正候補とする。
