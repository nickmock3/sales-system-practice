# 017 フロントエンドの商品マスタ画面を作成する

## 目的

商品マスタをブラウザから確認・登録できるようにし、商品履歴を追加する業務ルールを画面から学習できるようにする。

## 対象範囲

- Next.js フロントエンドに商品マスタ画面を追加する。
- 商品一覧を表示する。
- 商品の詳細と履歴を確認できるようにする。
- 商品の新規登録フォームを作成する。
- 既存商品の履歴追加フォームを作成する。
- 商品 API 呼び出し処理と TypeScript 型を整理する。
- ローディング、入力エラー、API エラーを画面上で確認できるようにする。

## 前提仕様

- 商品マスタの変更は既存行の更新ではなく、履歴レコードの追加で表現する。
- 商品の適用履歴は、対象日以前で一番新しい履歴を使う。
- 商品履歴の標準単価は、得意先別商品単価が存在しない場合のフォールバック単価として売上入力で使われる。
- 商品履歴の税区分は、売上日以前で一番新しい税率を決めるために使われる。
- 得意先別商品単価は商品履歴ではなく、`specs/unit-prices.md` で定義する別マスタとして管理する。
- バックエンド API はダミー認証を使うため、フロントエンドから必要なヘッダーを付与する。

## 実装方針

- まずは学習用として、装飾よりも商品情報と履歴の確認しやすさを優先する。
- 一覧、詳細、登録、履歴追加を同じ画面内で扱える構成にする。
- 商品詳細では、標準単価が得意先別商品単価のフォールバックであることが分かる表示にする。
- 商品詳細から、後続の得意先別商品単価画面で対象商品に絞り込める導線を検討する。
- API のレスポンス型は TypeScript で定義し、画面側に ad hoc な `any` を広げない。

## 確認項目

- `bun lint` またはプロジェクトで定義されているフロントエンド検証コマンドが成功すること。
- 商品を新規登録できること。
- 既存商品に履歴を追加できること。
- 商品一覧と履歴表示が更新後の内容を反映すること。
- 標準単価、税区分、販売停止フラグが履歴追加後の一覧・詳細に反映されること。
- API エラー時に画面がクラッシュせず、ユーザーに原因が分かる表示になること。

## 完了メモ

### 実装した画面・コンポーネントの概要

- `frontend/src/app/products/page.tsx` に商品マスタ画面を追加した。
- 一覧、検索条件、選択中商品の詳細、商品履歴、商品新規登録フォーム、商品履歴追加フォームを同一画面で扱う構成にした。
- 商品詳細から `customer-product-prices?productId=...` へ移動できる導線を追加した。
- 標準単価が得意先別商品単価のフォールバックであることを一覧説明とフォーム補足に表示した。
- ローディング、空表示、通信エラー、認証・認可エラー、API エラー、入力エラーを画面上に表示するようにした。
- `frontend/src/app/globals.css` の `.surface` に `min-width: 0` を追加し、モバイル幅でテーブルがページ全体を横スクロールさせないようにした。

### 追加・変更した API クライアント処理

- `frontend/src/lib/api/index.ts` に共通 `apiFetch` を追加した。
- `apiFetch` で `NEXT_PUBLIC_API_BASE_URL` を使い、ダミー認証ヘッダーを一元的に付与するようにした。
- ダミー認証状態は `localStorage` に保存し、一般ユーザー、管理者、ログアウトを切り替えられるようにした。
- HTTP エラーを `ApiError` に変換し、`ValidationProblem` の `errors` をフォームへ反映できる形で保持するようにした。
- `frontend/src/app/products/_api.ts` に商品一覧、履歴取得、商品登録、履歴追加の API 関数を追加した。
- `frontend/src/app/products/_schemas.ts` で API レスポンスとフォーム入力を Zod 検証するようにした。
- `frontend/src/app/products/_types.ts` に商品画面で使う TypeScript 型と税区分ラベルを追加した。

### 実行した確認コマンドと結果

- `cd frontend && bun lint`: 成功
- `cd frontend && bun tsc --noEmit`: 成功
- `cd frontend && bun run test`: 成功
- `cd frontend && bun run test:e2e`: 成功
- `cd frontend && bun lint && bun run test && bun run test:e2e`: 成功
- Browser / Playwright で `http://localhost:3000/products` をデスクトップ幅とモバイル幅で確認した。
- バックエンド API 未起動時に通信エラーが画面上に表示されることを確認した。
- モバイル幅でページ全体の横スクロールが発生しないことを確認した。

### 残した制約や次タスク候補

- Playwright は API モックで確認した。実バックエンド API と SQLite/Oracle を使う結合確認は別途実施する。
- `apiFetch` は商品画面用に導入したため、今後の得意先、税率、得意先別単価画面でも共通利用する。
- ダミー認証 UI は商品画面内で実装した。複数画面で使い回す段階で共通ヘッダーコンポーネントへ切り出す。

## 追加調整メモ

- 初期表示で一覧・詳細・フォーム上部を確認しやすくするため、商品マスタ画面のタイトル領域、検索条件、エラー表示の縦余白を圧縮した。
- 検索条件は説明文を削り、見出しと入力行を中心にしたコンパクトな構成へ変更した。
- 検索バーと商品一覧を同じ `surface` に統合し、検索結果が検索欄直下に表示される関係を明確にした。
- 選択中の商品パネルは現在値サマリーとして再構成し、一覧横で商品コード、商品名、単価、税区分、適用開始日を読みやすくした。
- 検索バー統合後に左カラム幅を超えて表示が歪んでいたため、検索バー内の列幅、ラベル幅、ボタン余白を調整して `surface` 内に収まるよう修正した。
- 商品未選択時は商品履歴追加フォームの入力欄を表示せず、対象商品を選択する空状態を表示するようにした。
- 商品一覧の空状態をテーブル行ではなく中央寄せの空状態として表示し、検索結果がないことを分かりやすくした。

- `cd frontend && bun run test:e2e`: 成功
