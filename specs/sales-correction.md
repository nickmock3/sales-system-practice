# 売上訂正仕様

## 目的

登録済みの売上に入力間違いがあった場合でも、過去の売上記録を直接更新せず、取消と再登録によって訂正内容を追跡できるようにする。

売上は過去に発生した取引の証跡として扱うため、登録済みの売上ヘッダーと明細は原則更新しない。

## 基本方針

- 登録済み売上は直接更新しない。
- 入力間違いは、元売上を取り消す取引を追加して表現する。
- 正しい内容が必要な場合は、取消後に正しい売上を新規登録する。
- 元売上、取消売上、再登録売上の関係を ID で追跡できるようにする。
- 状態変更は `Sales` の現在値カラムではなく、状態履歴として追記する。
- 取消理由、取消日時、取消実行者を状態履歴または訂正関係の監査情報として残す。
- 集計では、有効売上と取消売上を区別できるようにする。

## 訂正パターン

### 取消のみ

二重登録や完全な誤登録など、売上を存在しなかった扱いにしたい場合は取消のみを行う。

取消後、元売上は参照可能なまま残し、通常の有効売上集計からは除外する。

### 取消 + 再登録

得意先、商品、数量、単価、売上日などに誤りがあり、正しい売上が必要な場合は以下の流れにする。

1. 元売上を取り消す。
2. 正しい内容で売上を新規登録する。
3. 新しい売上から元売上を参照できるようにする。

学習用の初期実装では、差額訂正ではなく取消 + 再登録を基本とする。

## データ

初期実装から、売上本体、状態履歴、訂正関係を分離する。

`Sales` は売上そのものを表し、登録後は原則更新しない。

```text
Sales
- Id
- SalesDate
- CustomerId
- CustomerVersionId
- TotalAmount
```

`SaleDetails` は元売上登録時の明細を保持し、取消時にも直接更新しない。

```text
SaleDetails
- Id
- SaleId
- ProductId
- ProductVersionId
- Quantity
- UnitPrice
- TaxRate
- TaxAmount
- Amount
```

`SaleStatusHistories` は売上の状態遷移を表す。

```text
SaleStatusHistories
- Id
- SaleId
- Status
- Reason
- ChangedAt
- ChangedBy
```

項目の意味:

- `Status`: 売上の状態
- `Reason`: 状態変更理由
- `ChangedAt`: 状態変更 UTC 日時
- `ChangedBy`: 状態変更を実行したユーザー名

初期状態では以下の状態を扱う。

```text
Active
Canceled
```

将来、以下のような状態を追加できるようにする。

```text
CorrectionRequested
CorrectionApproved
CorrectionRejected
```

現在状態は、対象売上の `SaleStatusHistories` の最新行から導出する。

`SaleCorrections` は、元売上、取消売上、再登録売上の関係を表す。

```text
SaleCorrections
- Id
- OriginalSaleId
- CorrectionSaleId
- CorrectionType
- Reason
- CreatedAt
- CreatedBy
```

項目の意味:

- `OriginalSaleId`: 訂正対象の元売上 ID
- `CorrectionSaleId`: 取消売上または再登録売上の ID
- `CorrectionType`: `Cancellation` または `Replacement`
- `Reason`: 訂正理由
- `CreatedAt`: 訂正関係を作成した UTC 日時
- `CreatedBy`: 訂正を実行したユーザー名

## 取消時のルール

- 存在しない売上は取り消せない。
- 既に取消済みの売上は再度取り消せない。
- 取消売上自体は取り消せない。
- 取消理由は必須とする。
- 取消処理はトランザクションで実行する。
- 取消対象の元売上には `Canceled` の状態履歴を追加する。
- 取消を表す売上レコードを追加する場合は、元売上と逆符号の数量・金額を持つ明細を作成する。
- 取消売上には `Active` の状態履歴を追加する。
- 元売上と取消売上の関係を `SaleCorrections` に `CorrectionType = Cancellation` で保存する。

初期実装では、集計を分かりやすくするため、取消売上を追加して金額を逆符号で保持する。

## 再登録時のルール

- 再登録は通常の売上登録と同じ履歴取得・金額計算ルールを使う。
- 再登録売上には `Active` の状態履歴を追加する。
- 再登録売上が訂正元を持つ場合は、`SaleCorrections` に `CorrectionType = Replacement` で元売上との関係を保存できる。
- 再登録時点ではなく、再登録する売上日のマスタ履歴と税率を適用する。

## 一覧・詳細表示

売上一覧では以下を表示できるようにする。

- 売上状態
- 最新状態の変更日時
- 元売上 ID
- 訂正種別
- 訂正理由

通常業務の一覧では、初期表示は最新状態が `Active` の通常売上を対象とする。

監査確認では、最新状態が `Canceled` の売上と、取消売上も含めて表示できるようにする。

## 集計方針

売上集計では用途に応じて以下を分ける。

- 有効売上集計: 最新状態が `Active` の通常売上を対象にする。
- 監査用取引集計: 通常売上と取消売上を含め、逆符号の取消売上で相殺する。

初期実装では集計 API は作らず、一覧 API の絞り込みで状態を確認できるところまでを対象とする。

## 認可

- 売上取消 API は業務更新のため `MasterMaintainer` を要求する。
- 取消済みを含む一覧・詳細の参照は `AuthenticatedUser` を要求する。

## テスト観点

- 売上登録時に `Active` の状態履歴が追加される。
- 登録済み売上を取り消せる。
- 取消後、元売上に `Canceled` の状態履歴が追加される。
- 状態履歴に取消理由、変更日時、変更実行者が保存される。
- 取消売上と元売上の関係が `SaleCorrections` に保存される。
- 取消売上の金額と数量が元売上と逆符号になる。
- 既に取消済みの売上は再度取り消せない。
- 取消売上自体は取り消せない。
- 取消理由が空の場合はバリデーションエラーになる。
- 通常一覧では有効売上だけを取得できる。
- 監査用の一覧では取消済み売上と取消売上を確認できる。
- 認証なしでは売上取消 API にアクセスできない。
- `MasterMaintainer` ロールなしでは売上取消 API にアクセスできない。
